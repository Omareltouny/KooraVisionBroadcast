# KooraVision BroadAgents

**Match moments, written for each fan, in three languages, and replayed in 3D.**

KooraVision BroadAgents is a multi-agent system that reads a stream of football match events, finds the moments worth telling, and writes them as broadcast lower thirds and as personal notes for different fans in English, Arabic and Spanish. A checking agent rejects any text that adds a number, a name or a claim the match data does not support. Selected moments can be replayed in 3D, including the view through a player's eyes.

Built for the Microsoft hackathon, multi-agent category.

**Live page:** https://omareltouny.github.io/KooraVisionBroadcast/  
**Demo video:** https://youtu.be/vacon-GgqGM

> All clubs, players, stadiums and matches are fictional and generated by software. Nothing here is real match data or a real league.

## What it does

1. **Interpret** finds the moments: goals, big saves, pressing spells, comebacks, substitute impact, star performances, full time.
2. **Explain** turns each moment into a fact packet: the only numbers and names the writers may use.
3. **Narrate** writes each moment in English, Arabic and Spanish, in a broadcast voice and in a fan voice, with templates or a language model.
4. **Verify** checks every text against the fact packet. Wrong digits, names that are not in the facts, number words, unsupported "won" or "match ended" claims, the wrong script and over-long lines are rejected.
5. **Broadcast desk** and **Fan desk** run side by side. The first picks and ranks lower thirds. The second builds a feed per fan profile and decides what deserves a push notification.
6. **Publish** writes the outputs, and the match desk page shows them.

The **3D replay** tab rebuilds two goals in 3D next to the fan text for the same moment:

* a decoy run that drags a defender away and opens the space for the cutback;
* a player scanning the pitch before the ball reaches him, with a camera that shows his view.

## Microsoft technology used

* **Microsoft Agent Framework**: the workflow (Interpret, Explain, Narrate, Verify, the two desks, Publish) and the writer agent are built on it.
* **GitHub**: the repository.
* **GitHub Actions**: runs the tests, the model, the offline replay and the scene builder on GitHub's servers.
* **GitHub Pages**: hosts the match desk page.

## Honest disclosures

* The writer model is **not** a Microsoft model. It is a free third-party model on Groq (`openai/gpt-oss-120b`), called through the Agent Framework's OpenAI-compatible client. Pointing it at Microsoft Foundry is a change of environment variables (`KV_LLM_URL`, `KV_LLM_MODEL`, `KV_LLM_KEY`), not a code change. We did not run it on Foundry.
* Model answers are **cached** (`demo/llm_cache.json`), so the demo replays without any model or key.
* **Arabic model text is held for a native reader.** The checker cannot judge grammar. A reviewer approves drafts on the Arabic review tab, and only approved drafts replace the template text. Spanish is machine-assisted and has not had a native review.
* The **3D replays are illustrative reconstructions**. Ball events, minutes and score are the generated match events. Player positions come from synthetic tracking built from those events. The decoy run, the marker following him and the scanning player's head direction are authored on top and are not claimed to show how real players move.
* The Arabic and Spanish 3D captions are short templates.

## Run it

```
pip install -e ".[agents,dev]"
python -m pytest -q
python -m eventgen.cli generate --seed 7 --stories config/stories.example.yaml --out /tmp/a
python -m kvagents run /tmp/a --out /tmp/out                    # templates only, no model needed
python -m kvagents run /tmp/a --out /tmp/out --model-cache demo/llm_cache.json --offline   # replay the saved model answers
python -m kvagents.reconstruct /tmp/a /tmp/a/tracking.jsonl --out demo/scenes
python tools/build_site.py                                      # writes site/index.html
```

To run a model in GitHub instead of on your computer, see `docs/RUN-IN-GITHUB.md`.

## Known limits

* The checker catches wrong facts, not bad grammar. Spanish drafts can mix in English phrases and the checker does not catch that.
* The Gemini backup path is written but was not run.
* Interpret has no momentum-swing or quiet-then-burst detector yet.
* Synthetic tracking has loose marking, so the 3D "space" is visible but not dramatic.
